Duranta openairinterface5g Documentation Overview¶

This page is the entry point to the Duranta openairinterface5g documentation. It links to general information, tutorials, design documents, images, libraries, radios, testing and developer tools.

Important

Keep your repository rebased on develop, or read the documentation of the version you are using, so that it matches the features available in your repository. If you pulled develop some time ago, your repository may now be behind it.

More general information is available in the OpenAirInterface GitLab wiki.

General¶

  • Project overview: introduction, licensing, repository structure and community support
  • Feature set: supported features
  • Supported hardware and operating systems: tested CPUs, NICs and accelerators
  • Key performance indicators: KPIs of the RAN and UE stack
  • Getting the sources: how to download the sources
  • Building OAI: how to build the sources
  • Packages: build and install Deb/RPM packages of OAI
  • Tuning and security: performance and security considerations
  • Security policy: report vulnerabilities and find supported release information
  • Environment variables: environment variables used by OAI
  • Roadmap: planned development milestones and priorities
  • Changelog: notable changes delivered in each release

Tutorials¶

Getting started with 5G¶

  • OAI 5G core network: deploy the OAI 5G core network with Docker
  • OAI gNB with a COTS UE: end-to-end 5G SA setup with a commercial UE (Quectel module)
  • OAI NR-UE: end-to-end 5G SA setup with the OAI UE
  • Multiple OAI NR-UEs with the RFsimulator: run several OAI UEs in one setup, with namespaces or Docker

Running OAI¶

  • Running the gNB: simulators, hardware, SDAP and custom DRBs, IF setups and arbitrary frequencies, MIMO
  • Running the UE: configuration and modes (phy-test, do-ra, noS1)
  • gNB MAC usage: scheduler, periodic output and configuration options
  • gNB RRC usage: RRC functions, periodic output and configuration options
  • Setting the gNB frequency: configure the gNB carrier frequency and bandwidth (ARFCN)
  • 5G NSA setup: non-standalone setup with an OAI eNB and gNB (may be outdated)
  • NTN setup: non-terrestrial network setup for LEO and GEO satellites
  • Handover: F1 (intra-gNB), N2 and Xn (inter-gNB) handovers
  • F1-based NR-DC: NR dual connectivity with one CU and FR1/FR2 DUs
  • Positioning reference signal (PRS): Rel-16 PRS positioning with the gNB and NR-UE
  • E2 agent: deploy the gNB with the E2 agent and the FlexRIC near-RT RIC
  • E3 agent: build, configure and connect real-time dApps integrated in the gNB
  • Sidelink: Sidelink operation between UEs

Functional splits¶

  • F1 design: CU/DU split and implementation status
  • E1 design: CU-CP/CU-UP split and how to run it
  • O-RAN 7.2 fronthaul: run the gNB with O-RAN 7.2 radio units
  • OAI O-RU: configure, build and run the native OAI O-RU executable
  • Native 7.2x fronthaul library: architecture and implementation of the DPDK-based fronthaul stack
  • OAI-VNF and OAI-PNF: FAPI/nFAPI split, with general remarks on FAPI/nFAPI
  • nFAPI internals: VNF/PNF P5/P7 message processing and flowcharts
  • NVIDIA Aerial and Foxconn: OAI L2 with the NVIDIA Aerial L1 over FAPI and a Foxconn RU

Hardware acceleration¶

  • LDPC accelerators (AMD/Xilinx T2, Intel ACCs, ORS Aurora): LDPC offload through O-RAN AAL/DPDK BBDEV or XDMA (Aurora)
  • NR-UE with the GPU LDPC decoder: offload the UE LDPC decoder to a GPU
  • GPU LDPC decoder: test and profile the CUDA/HIP decoder
  • GPU-accelerated channel simulation: run the channel model on the GPU with CUDA

Simulators¶

  • Physical simulators: standalone PHY test programs (physims) and how to run them
  • Channel simulator: channel models and their configuration
  • UE positioning in a digital twin: localize a UE using ray-tracing channel emulation
  • L2 simulator: test L2 and above over nFAPI with simulated UEs (4G)

Legacy¶

These documents are unmaintained and no longer valid:

  • L2 simulator without S1: two-host deployment without a core network
  • L2 simulator with S1: two-host deployment with an EPC
  • 4G L1 simulator: we recommend the RFsimulator instead
  • 4G device-to-device (D2D) emulator: unfinished, steps may not be enough

Designs¶

  • Software architecture: general notes
  • L1 flow graph in the gNB: overview of the gNB L1 threads
  • L1 threads in the NR-UE: UE PHY/MAC interface and multi-threading design
  • F1AP message library: encoding, decoding and testing of F1AP messages
  • GTP-U design: user-plane tunnels for S1-U, N3 and F1-U
  • Xn design: Xn-C between gNBs, XnAP procedures and Xn handover
  • NRPPa call flow: UL-TDOA positioning call flow
  • UE 5G NAS: 5GS NAS protocol and OAI implementation status
  • Beamforming: configuration and scheduler implementation
  • gNB RACH processing: receive and process random-access channel samples
  • UL MIMO: uplink MIMO and how to test it with the ULSCH simulator

Container Images¶

  • Building images: build the OAI Docker/Podman images
  • 5G with the RFsimulator: deploy a full 5G SA setup with containers
  • 4G with the RFsimulator: deploy a full 4G setup with containers
  • O-RAN 7.2 with a VVDN O-RU: deploy the gNB and O-RU integration with containers
  • Physical simulators in OpenShift: build images on an OpenShift cluster

Libraries¶

General¶

  • T tracer: generic tracing tool (VCD, Wireshark, GUI, recording for later analysis)
  • OPT: tracing to Wireshark
  • Configuration module: API to read parameters from configuration files and the command line
  • Logging module: console logging for all OAI components
  • Shared object loader: load optional libraries (radios, coding, ...) at run time
  • Thread pool: used in L1
  • Actor utility: single-threaded actors with single-producer/single-consumer input queues
  • Inter-task interface (ITTI): typed message queues, timers and socket events between threads
  • LDPC implementation: built as a shared library
  • Time management: timers in realtime and simulation modes

Radios¶

Radio drivers under radio/ with their own documentation. The other SDRs (AW2S, LimeSDR, ...) have none.

  • RFsimulator: replaces the radio to test OAI without RF hardware
  • USRP: Ettus USRP devices through UHD
  • BladeRF: BladeRF 2.0 micro setup and configuration
  • I/Q player: driver usage
  • I/Q record and replay: general documentation
  • O-RAN 7.2 fronthaul driver (fhi_72): developer notes on the xran-based driver
  • Ethernet fronthaul drivers: eCPRI split 8 and IF4.5 split 7 transport over Ethernet
  • vrtsim: shared memory radio interface
  • RF emulator: runs without a radio, drops TX and generates noise as RX
  • ZeroMQ (zmq): exchange samples between processes over ZeroMQ

Special-purpose libraries¶

  • Scopes: xForms and imgui based scopes
  • Telnet server: monitoring and control
  • Web server: web interface for monitoring and debugging
  • RT data recording app: record synchronized gNB and UE data sets in SigMF format

Testing¶

  • Unit tests: unit testing setup
  • Test benches: CI setup and links to pipelines
  • CI framework: custom framework to run end-to-end tests
  • Component tests (in tests/): - CU-UP tester: performance test of the CU-UP over E1 and GTP - CU-NRPPa tester: test NRPPa and NGAP positioning messages with the AMF - UE NAS tester: test UE NAS procedures with the AMF, without RAN - XNAP tester: validate Xn setup over real SCTP and ASN.1 without a full RAN stack

Developer tools¶

  • Repository agent guidelines: build, coding and verification conventions for coding agents
  • Contribution requirements: licensing, DCO, commit and contribution requirements
  • Contribution guidelines: working practices, code style and review process
  • Git guide: commit signing, branch management, submodules, recovering from mistakes, reusing conflict resolutions (rerere)
  • Cross-compilation: cross-compiling OAI for ARM
  • clang-format: code formatting
  • Formatting check: detects clang-format errors
  • cppcheck: static code analysis
  • Sanitizers: running with ASan, UBSan, MSan and TSan
  • include-what-you-use (iwyu): detects #include errors
  • Docker development environment: Ubuntu 24 based
  • Plotting tools: generate PHY performance plots from simulator results
  • Performance monitoring: tools to monitor the computing performance of OAI
  • Documentation best practices: guidelines for writing documentation
  • Documentation website: build, preview and validate the documentation website (Zensical)
